# 0.3.4 学习任务暂停与继续修复（2026-10-19）

本次只同步基于 91f18e631db40a6a9d8ec0bd655645b0f3ec4af8 的任务状态修复。版本仍为 0.3.4；未包含本机另一阶段的独立学习模型配置改动。私人数据库、配置、日志、截图、模型和本机备份均不在同步范围。

## 根因与修复

使用临时 SQLite、合成任务和生产页面，加载该基线的 learning.js 实点暂停：PATCH 已发送，事务提交及 GET 回读为 paused，但旧成功提示处于视口之外，卡片没有明确的“继续学习”入口。这是隔离复现结论，不代表读取或核实过用户正式数据库中的历次操作。

暂停后原逻辑会移除当前学习卡片、重绘并滚动到任务列表，通用提示留在上方；当前学习区按钮也缺少专门的暂停处理中提示。状态枚举校验未限制已完成、已取消任务重新激活。待核请求在 GET 状态匹配时还会跳过原事务回执核对，失败后核对入口可能未立即重建。

现在开始、暂停、继续、完成使用一致的处理中反馈、事务回执验证及独立 GET 回读。反馈独立于任务卡片重绘并吸顶显示，复用原草稿存储键跨刷新保留；再次读取发现当前状态变化时明确显示变化。paused 卡片提供“继续学习”，恢复后进入当前学习区。失败显示原因，核对入口立即出现；回执丢失后只核对同一 request_id 和正文，不另建请求。

后端继续使用原 BEGIN IMMEDIATE、请求指纹与事务内回执。done/cancelled 不能恢复 pending/active/paused/deferred；终态卡片不提供开始、暂停、继续或延期。done → cancelled 保持原计划移除兼容。纯重复状态不更新任务行、更新时间和来源；同 ID 回放仍优先返回原回执，不能改变后来的终态。任务写入异常返回 database 类别和安全错误说明。

不改变数据库结构、旧任务 ID、学习记录或测验历史。旧任务模式及 paused 数据使用合成迁移夹具验证；正式私人数据未读取、未迁移。暂停只改变任务状态，没有正式计时器，不自动记录分钟、创建任务或进度。

阶段05提醒保留原规则：任务状态变化使旧提醒快照失效；新有效提醒仍通过原事务开始任务。任务暂停与“今日暂停提醒”分别处理，没有改变频率、候选任务或模型路由。
